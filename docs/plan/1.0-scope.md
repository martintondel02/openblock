# OpenBlock 1.0.0 scope and delivery plan

> Status: active delivery plan · Last updated: 2026-11-25
> Depends on: [Roadmap](00-roadmap.md), [Milestones](01-milestones.md), [Decisions](../decisions.md)
>
> This document defines what "1.0.0" means for this project. It is updated as
> waves land and is the checklist the 1.0.0 and 1.0.1 audits use. It is deliberately
smaller than full Minecraft parity: 1.0.0 is a polished, self-hostable voxel
sandbox with the core survival loop, mobs, sound, and working multiplayer. The
Tier-2 feature track (dimensions, redstone, WASM mods, controllers, QUIC/TLS) is
post-1.0.

## 1.0.0 feature checklist

### World
- [x] Infinite deterministic terrain: 5 biomes (existing), blended heights,
      trees/features (existing), **caves and ravines**, **ore veins** (coal,
      iron, copper), surface cave entrances, no missing chunks at the edge of
      the render distance.
- [x] Safe, stable world spawn: a candidate column is generated before it is
      accepted (dry solid surface, no tree/boulder above, two clear cells) and
      persisted in `spawn.txt`; respawn points no longer move across restarts.
- [x] Day/night cycle with sky, sun/moon/stars, fog (existing).
- [ ] Weather? _Deferred post-1.0_ (documented).

### Survival loop
- [x] Health/hunger, fall damage, starvation, regeneration, death/respawn
      (existing v0.0.7).
- [x] Mining with tool requirements/speeds and durability; block drops as item
      entities with a 3 m pickup magnet (existing v0.0.8/0.0.9).
- [~] **Crafting**: 1.0 ships the recipe-book crafting UI (25 recipes, table
      gating, availability/ingredient feedback) instead of a spatial grid; a
      3x3 shaped grid is post-1.0. No torches/stairs/glass in 1.0 (`torches &
      light` are post-1.0; darkness/mob spawning uses time-of-day and depth).
- [x] **Smelting**: furnace block + fuel + smelt recipes; charcoal/coal, iron
      ingots, cooked food (glass deferred with the glass block).
- [x] **Ore progression**: stone tools -> coal -> furnace -> iron tools and
      armor; tool/armor durability, armor damage reduction.
- [x] **Food loop (simplified)**: apples (existing), raw/cooked beef and
      porkchop from animals, furnace cooking; hunger tuned so the loop is
      playable. Farming/crops are post-1.0.
- [x] **Mobs**: cows/pigs/sheep/chickens (wander/flee) and zombies (night/depth
      spawning, chase/attack, sun burn, despawn), drops, player attack and
      damage/knockback; no breeding/villagers/projectiles in 1.0.
- [x] **Chests** for storage (server-authoritative contents; UI).
- [~] Torches/block-light are **post-1.0**; 1.0 mob spawning uses time-of-day
      and depth (documented simplified darkness model).

### Multiplayer
- [x] `ob_protocol` v2 message catalog + JSON/TCP framing (interim transport;
      QUIC/TLS post-1.0) and handshake/content hash checks.
- [x] Dedicated `openblock-server` binary: world load/create, listen, config,
      console commands, chat, whitelist/max players, autosave, graceful stop.
- [x] Client connect flow: `--connect HOST:PORT` with connect/loading/failure
      screens; a full title screen / server browser is scheduled for 0.2.0.
- [x] World replication: chunk streaming with interest radius, block edits
      broadcast + remesh, player avatars, chat overlay, roster, server status/
      disconnect reasons. Name tags over avatars polish in 0.2.0.
- [x] Server-authoritative survival: inventories/vitals/equipment/actions/
      containers/mobs/items validated and replicated; player movement stays
      client-side in 1.0 (documented limitation, anti-cheat post-1.0).
- [x] Save/load multiplayer world + reconnect by name; multi-client loopback
      tests cover join/edits/loot/mobs/containers/death; LAN manual demo run.

### Audio
- [x] Procedural sound engine (runtime PulseAudio on Linux, silent stub
      elsewhere — no ALSA/cpal build deps) with material footsteps,
      break/place, hurt/death, eat/craft/pickup, tool break, UI and ambient
      wind/music loops; volumes and mute in settings; graceful no-device fallback.

### UI/UX
- [x] Title screen: Continue, New world, Load world, Multiplayer (direct
      connect), Settings, Quit; world seed/name input. **Delivered in 0.2.0.**
- [x] Pause/settings screen (existing) with Audio tab, controls rebinding for
      movement/actions, render distance/FOV/sensitivity. **GUI scale shipped in
      1.0.1, not 1.0.0** (Auto/75/100/125/150, Display row, persisted; see
      [client GUI scale](../client-gui-scale.md)).
- [x] HUD: hearts/hunger/armor, crosshair, hotbar, hurt feedback, chat, player
      roster, toasts, F3 overlay with multiplayer/network stats, day/night and
      mob counts. Breath/boss bars are post-1.0.
- [x] Inventory/crafting/furnace/chest screens: readable spacing, click-to-cursor
      item movement, tooltips/info lines, durability bars, armor slots, remote
      server-authoritative container windows.
- [x] Accessibility: remappable keys (17 actions, duplicate rejection, reset),
      reduced-motion option, persisted HUD visibility, readable menus down to
      960×540, and GUI scale (Auto/75/100/125/150, shipped in 1.0.1);
      colour-blind presets remain post-1.0 (documented).
- [ ] Localization? _Post-1.0_ (documented), English only for 1.0.

### Persistence / server ops
- [x] Save v4 plus sidecars covering mobs (`mobs.txt`), block entities
      (`block_entities.txt`), equipment, items, network players and the world
      spawn (`spawn.txt`, additive); automatic migration from v1-v4; crash-safe
      atomic writes; backup/restore scripts and docs (server-side backup command
      remains a CLI/script workflow in 1.0).
- [x] Dedicated server packaging: hardened systemd unit/sysusers/tmpfiles,
      dependency-free multi-stage container image + compose, admin handbook
      (quickstart/config/administration/security/backup/upgrade/troubleshooting),
      firewalld config, load-test bots and dependency check.
- [x] Client packaging: Flatpak + COPR RPM manifests are versioned 1.0.0 and
      the desktop/metainfo files are maintained. **Artifacts are staged, not
      published:** the v1.0.0 release assets are screenshots only, and the
      Flatpak/COPR builds still need their release tarball/vendor sources (see
      [1.0.1 audit](1.0.1-audit.md)).

### Quality gates for 1.0.0
- [x] `cargo test --workspace`, clippy `-D warnings`, fmt, rustdoc,
      architecture/docs checks green on Linux/Fedora/Windows/macOS CI (ignored
      GPU/measurement probes remain intentionally ignored).
- [x] Deterministic smoke/hash tests; save migration tests; protocol
      malformed/oversized/fuzz-ish and adversarial tests (security wave).
- [x] Performance: offscreen render benchmark gate holds; benchmarks published
      (worldgen 0.92 ms/chunk, tick p99 <=0.03 ms baseline, save 21-156 ms);
      automated 8-client load gate passes locally (tick p99 0.163 ms, 20 TPS,
      0 overruns >35 ms) and CI runs a 4-bot quick gate; the 4-vCPU reference
      capacity claim, 16/50-player rows and async-save remain 1.0.x gaps.
- [x] No bundled third-party assets; resource packs loaded locally only.
      Verified in the 1.0.1 audit: the only tracked non-code binaries are the
      project-generated screenshots under `docs/img/` and the CC0 icon; no
      Minecraft textures, sounds or other third-party game assets are bundled.
- [x] Docs: README feature list/screenshots/controls, CHANGELOG, packaging and
      admin docs, protocol/server specs, known limitations (final 1.0 polish in
      the release wave).
- [x] Strict end-to-end 1.0 acceptance sweep through public APIs: spawn/starter
      resources, full survival loop (wood -> stone -> iron -> food -> chest ->
      save/reload), multiplayer protocol v2 loop, edge/fuzz matrix, and two
      regressions found by the sweep (dead-player edits, unstable/unsafe spawn).
      See [1.0-acceptance.md](1.0-acceptance.md).

### Remaining 1.0.0 items after the gameplay acceptance sweep

The gameplay/server and client/UI slices are green and the 1.0.0 checklists are
settled. The only unchecked boxes above are deliberate post-1.0 items
(weather and localization); GUI scale moved from "post-1.0" to the 1.0.1 polish
line, and the release-packaging audit is recorded in
[1.0.1-audit.md](1.0.1-audit.md):

- the v0.2.0 front-end commit delivered the title screen, world select,
  direct-connect UI, controls rebinding and accessibility work, so those boxes
  are checked against the shipped code rather than the separate UI sweep;
- the 1.0.1 audit verified the no-bundled-third-party-assets rule and the
  packaging/manifest state;
- localization remains post-1.0 per the open questions below; the interactive
  server browser question is settled by the shipped direct-connect + recent
  servers UI.

Known accepted limitations of the shipped loop are listed in
[1.0-acceptance.md § Known accepted limitations](1.0-acceptance.md#known-accepted-limitations-10).

## Version wave plan (each wave ends in a tagged release + green CI)

> **Settlement note (1.0.1 audit).** Only `v0.0.3`–`v0.0.9`, `v0.1.0`, `v0.2.0`
> and `v1.0.0` were tagged. The 0.3.0–0.8.0 rows below were the original
> sequencing plan; that work was folded into the 1.0.0 hardening wave instead of
> shipping as separate releases, so do not look for those tags or changelog
> sections. The contents of each row still landed and are covered by the 1.0.0
> checklist and acceptance sweep.

| Version | Contents |
| --- | --- |
| 0.1.0 | Delivered: protocol v2 + dedicated server; client connect with replication/avatars; server-authoritative survival + containers + entity replication; audio; caves/ravines/ores; mobs/combat; packaging/ops; benchmarks. |
| 0.2.0 | Title screen / world select / direct-connect UI, controls rebinding, UI scale/accessibility, name tags and multiplayer UI polish; crafting-grid design decision (1.0 ships recipe-book). |
| 0.3.0 | Ores + furnace/smelting/iron tools; crafting grid + furnace UI; torch light; new blocks/textures. |
| 0.4.0 | Mobs & combat (passive + hostile, AI, drops, attack, damage/knockback) with server-side entities and rendering. |
| 0.5.0 | Farming/food variety, armor, chests, hunger balancing; multiplayer mob/item replication hardening. |
| 0.6.0 | Title screen/world select/connect UI, controls rebinding, UI scale, HUD/chat polish; persistence maturity (mobs/chests/crops/furnaces, migration tests, backups). |
| 0.7.0 | Server ops (config/commands/whitelist/backups/systemd/container), packaging (Flatpak/COPR), load/soak tests and docs. |
| 0.8.0 | Performance pass, accessibility, bug bash, documentation/spec alignment, screenshots. |
| 1.0.0 | Delivered: Early Access release with survival, multiplayer alpha, audio, front-end/keybinds, acceptance+load gates, docs/screenshots/packaging. |
| 1.0.1 | Strict post-release audit/polish: playtest bugs, UX polish, GUI scale, async-save investigation, performance/docs/security findings; audit record in [1.0.1-audit.md](1.0.1-audit.md). |

## Non-goals for 1.0.0 (documented as post-1.0)
Nether/End and other dimensions, redstone, WASM mods, controller support,
localization, full Minecraft parity block/item counts, QUIC/TLS anti-cheat
infrastructure, mobile/web, shader packs beyond the built-in visual options.

## Open questions

- Server-authoritative movement/anti-cheat: **settled for 1.0.x** as a
  documented limitation (client-side movement, server validation of edits and
  entity simulation); server physics is post-1.0 work.
- Torches/block-lighting: **settled** as post-1.0; 1.0 mob spawning uses the
  simplified time-of-day + depth model.
- Farming/crops: **settled** as post-1.0 (there was no separate 0.5.0 release
  wave); food comes from apples, animals and cooking.
- Interactive title-screen server browser: **settled** — 1.0/1.0.1 ship direct
  connect plus a recent-servers list; a public server browser is post-1.0.

## 1.0.0 release status (2026-11-25)

Released as Early Access with the checklists above satisfied except the items
explicitly accepted below. The automated acceptance scenario
([1.0-acceptance.md](1.0-acceptance.md)) covers the complete single-player loop
and a raw protocol-v2 multiplayer loop; the load gate and 10-minute soak are
documented in [08-measurements.md](08-measurements.md).

**Accepted for 1.0.0, scheduled after release:**
- Spatial 3×3 crafting grid (1.0 ships recipe-book crafting; networked crafting
  is single-player/menu only).
- Torches/block-light propagation, farming/crops, weather, beds, dimensions,
  redstone, more content tiers.
- TLS/authentication, server-side player physics/anti-cheat, PvP, LAN discovery.
- Colour-blind presets, controller support, localization (GUI scale moved to
  the 1.0.1 polish line).
- Windows/macOS real audio output (silent stub on those platforms in 1.0).
- Asynchronous world saves and the 4-vCPU/8-GiB reference capacity claim
  (16/50-player rows).
- WASM modding track and full content-pack SDK; resource packs are supported at
  runtime but no mod host exists yet.
- Published client/server artifacts for the in-tree RPM/Flatpak/container
  recipes (no binaries were attached to the v1.0.0 release; the manifests are
  staged and the release-asset/checksum gap is recorded in the
  [1.0.1 audit](1.0.1-audit.md)).

## 1.0.1 release status (in progress at 2026-11-25)

**1.0.1** is the strict post-release audit/polish update: playtest bugs, UX
polish (GUI scale, connect-panel layout), async-save/known-gap investigation,
and the performance/docs/security findings from the 1.0.0 review.
The documentation, security, metadata and packaging slice is tracked in
[1.0.1-audit.md](1.0.1-audit.md). The client GUI-scale and connect/loading
polish slice is implemented and verified in 1.0.1 (see
[client GUI scale](../client-gui-scale.md) and the `docs/img/v1.0.1-*`
screenshots).
