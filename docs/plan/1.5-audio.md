# 1.5 audio slice — procedural weather, fire, explosions and mob cues

> Status: implemented in the `v1.5-dev` audio slice · Last updated: 2026-11-25
> Owner slice: `crates/audio` only. The later client/render agent wires these
> clips to weather, lightning, fire, projectile and mob presentation state.
> Server, protocol, content, render and client files are intentionally untouched
> here.

## 1. Goal

The 1.0 bank (79 clips: 77 SFX variants plus wind and music loops) covered
footsteps, blocks, pickups, UI and player damage. The 1.5 slice adds procedurally
synthesised weather, fire, explosion, projectile and subtle mob cues without new
assets, build dependencies, `cpal` or a new device backend. Synthesis remains
deterministic: integer hashes and plain arithmetic only, no `rand`, `sin`, `exp`
or `powf`.

The generated bank is now **110 clips**:

| Part | Clips |
| --- | ---: |
| Legacy `Sfx` one-shot variants (8 materials, including new fire) | 86 |
| 1.5 one-shot variants | 18 |
| 1.5 ambient loop beds | 4 |
| Legacy wind + music beds | 2 |
| **Total** | **110** |

All 110 clips are resident mono PCM at 48 kHz: **4,723,134 frames / 18.0 MiB**
(excluding the small `Vec`/`Box` metadata). There is no streaming and no
allocation on the audio thread.

## 2. Clip registry

`ClipId` is the stable public registry for the 1.5 clips; `ClipKind` distinguishes
looping beds from one-shots. `Sfx` is unchanged for the 1.0 gameplay events.

| `ClipId` | `name()` | Kind | Variants | Nominal duration |
| --- | --- | --- | ---: | --- |
| `RainLoop` | `rain_loop` | Loop | 1 bed (6.50 s) | light/moderate rain |
| `RainHeavyLoop` | `rain_heavy_loop` | Loop | 1 bed (6.50 s) | heavy, darker rain |
| `SnowWindLoop` | `snow_wind_loop` | Loop | 1 bed (7.45 s) | soft snow/wind |
| `FireCrackleLoop` | `fire_crackle_loop` | Loop | 1 bed (5.55 s) | fire pops + bed |
| `ThunderDistant` | `thunder_distant` | One-shot | 2 | 4.20 / 4.55 s |
| `ThunderNear` | `thunder_near` | One-shot | 2 | 3.00 / 3.25 s |
| `LightningCrack` | `lightning_crack` | One-shot | 1 | 1.80 s |
| `Explosion` | `explosion` | One-shot | 2 | 2.20 / 2.40 s |
| `CreeperHiss` | `creeper_hiss` | One-shot | 2 | 1.60 / 1.70 s |
| `BowShoot` | `bow_shoot` | One-shot | 1 | 0.26 s |
| `ArrowImpact` | `arrow_impact` | One-shot | 1 | 0.20 s |
| `CriticalHit` | `critical_hit` | One-shot | 1 | 0.32 s |
| `SkeletonRattle` | `skeleton_rattle` | One-shot | 2 | 0.55 / 0.60 s |
| `SpiderChitter` | `spider_chitter` | One-shot | 2 | 0.50 / 0.58 s |

Loop durations are after the baked seam crossfade. One-shot durations are before
the mixer's 3 ms attack / 10 ms release.

`Material::Fire` is appended to the existing material family, so
`Sfx::Footstep(Material::Fire)`, `Sfx::BlockBreak(Material::Fire)` and
`Sfx::BlockPlace(Material::Fire)` already exist. The later client should map
`openblock:fire` in `audio_material_for` to `Material::Fire` so breaking/placing
fire uses the new dry-crackle variants.

## 3. Public API

```rust
pub const LOOP_FADE_SECONDS: f32 = 1.2;

pub struct ClipCue {
    pub clip: ClipId,
    pub gain: f32, // 0.0..=4.0
    pub rate: f32, // 0.5..=2.0
}
impl ClipCue {
    pub fn new(clip: ClipId, gain: f32, rate: f32) -> Self;
}

pub fn rain_intensity_gains(intensity: f32) -> (f32, f32); // (light, heavy)
pub fn thunder_cue(distance_m: f32) -> ClipCue;
pub fn explosion_cue(distance_m: f32) -> ClipCue;
pub fn constant_power_pan(pan: f32) -> (f32, f32); // (left, right)
pub fn world_pan(listener_position: [f32; 3], yaw: f32, position: [f32; 3]) -> f32;
pub fn distance_attenuation(distance: f32, max_distance: f32) -> f32;

impl AudioEngine {
    // New in this slice:
    pub fn set_ambient_volume(&mut self, volume: f32);
    pub fn set_loop_volume(&mut self, clip: ClipId, volume: f32) -> bool;
    pub fn stop_loop(&mut self, clip: ClipId) -> bool;
    pub fn loop_volume(&self, clip: ClipId) -> Option<f32>;
    pub fn play_clip(&mut self, clip: ClipId, gain: f32, pan: Option<f32>) -> bool;
    pub fn play_cue(&mut self, cue: ClipCue, pan: Option<f32>) -> bool;
    pub fn play_clip_world(&mut self, clip: ClipId, position: [f32; 3], gain: f32) -> bool;

    // Existing API, unchanged:
    pub fn set_master_volume(&mut self, volume: f32);
    pub fn set_sfx_volume(&mut self, volume: f32);
    pub fn set_music_volume(&mut self, volume: f32);
    pub fn set_listener(&mut self, position: [f32; 3], yaw: f32);
    pub fn play_sfx(&mut self, sfx: Sfx);
    pub fn play_sfx_at(&mut self, sfx: Sfx, gain: f32, pan: Option<f32>);
    pub fn play_sfx_world(&mut self, sfx: Sfx, position: [f32; 3], gain: f32);
}
```

`play_clip` and `play_cue` return `false` for looping clips; loops are controlled
only through `set_loop_volume` / `stop_loop`. All gains, pans and rates are
sanitised at the public boundary; non-finite values never reach the mixer.

### 3.1 Gain, pitch and pan

- `thunder_cue(distance)` chooses `ThunderNear` at `<= 64 m` and
  `ThunderDistant` beyond that. Gain falls from 1.0 to a 0.05 floor by 320 m;
  playback rate falls from 1.0 to 0.82, so distant thunder is deeper. Distances
  are clamped to `0..=512 m`; `NaN` is treated as the far horizon.
- `explosion_cue(distance)` uses `Explosion`, quadratic gain falloff over 96 m
  (zero at 96 m) and rate 1.0 → 0.88. Skip zero-gain cues.
- `rain_intensity_gains(i)` returns the two rain-bed targets. Both are zero at
  `i = 0`; the light bed peaks at 0.65 around `i = 0.5`; the heavy bed grows to
  0.90 at `i = 1.0`. Finite out-of-range values are clamped; non-finite input
  means "no rain".
- `world_pan` returns a yaw-relative pan capped at ±0.8; `constant_power_pan`
  turns a pan into left/right gains whose squares sum to one. `play_clip_world`
  applies the same 24 m linear attenuation and pan as the existing
  `play_sfx_world`. Use `play_cue` plus `world_pan` for thunder/explosion ranges
  larger than 24 m.
- `play_clip`/`play_cue` otherwise apply the same deterministic variant and
  small automatic pitch variation as `play_sfx`. `play_cue` overrides the rate
  with the sanitised `ClipCue.rate`.

### 3.2 Loop behaviour

The four 1.5 beds are mixed on a new ambient bus:
`master × ambient × 0.65 × target`. The legacy wind/music bed remains on the
music bus.

`set_loop_volume` writes an atomic target. The mixer moves each bed gain linearly
by `1 / (1.2 × output_rate)` per output sample, so every start, stop or volume
change settles in at most 1.2 s. The final sub-step snaps to the target, a
stopped bed stops advancing at exact zero, and a loop at zero is not advanced.
There is no hard cut, so start/stop/volume changes are click-free even if the
target changes mid-ramp. Beds are centre-panned mono; all four are resident.

One-shots use the existing 16-voice pool with quietest-voice stealing, 3 ms
attack, 10 ms release, constant-power pan and the soft limiter, so different
one-shots overlap and are never hard-clipped. Same-group requests remain gated
by short per-clip cooldowns (thunder 0.50–0.60 s, lightning 0.20 s, explosion
0.08 s, creeper 0.15 s, bow 0.05 s, arrow 0.04 s, crit 0.03 s, skeleton 0.15 s,
spider 0.10 s, XP 0.03 s, level-up 0.40 s).

## 4. Client integration recipe

The client already calls `set_listener` in both the single-player and network
paths (`crates/client/src/lib.rs` and `crates/client/src/net_app.rs`); keep that
call and add the loop/event wiring next to it or in the weather/fire update.

```rust
use ob_audio::{
    AudioEngine, ClipId, explosion_cue, rain_intensity_gains, thunder_cue, world_pan,
};
```

1. **Weather beds.** On each weather update (or every frame; repeated targets
   are cheap), choose the precipitation type from the client's read-only biome
   data and set the beds:

   ```rust
   if snowing {
       engine.set_loop_volume(ClipId::RainLoop, 0.0);
       engine.set_loop_volume(ClipId::RainHeavyLoop, 0.0);
       engine.set_loop_volume(ClipId::SnowWindLoop, 0.55 * intensity);
   } else if raining {
       let (light, heavy) = rain_intensity_gains(intensity);
       engine.set_loop_volume(ClipId::RainLoop, light);
       engine.set_loop_volume(ClipId::RainHeavyLoop, heavy);
       engine.set_loop_volume(ClipId::SnowWindLoop, 0.0);
   } else {
       engine.stop_loop(ClipId::RainLoop);
       engine.stop_loop(ClipId::RainHeavyLoop);
       engine.stop_loop(ClipId::SnowWindLoop);
   }
   ```

   `intensity` is `0.0..=1.0`. Stopping is a 1.2 s ramp, not a cut. The ambient
   bus defaults to 1.0; add an `ambient_volume` setting later or map the existing
   music slider until the UI gains that row.

2. **Fire bed.** Derive a smooth 0..1 target from the number and proximity of
   nearby fire blocks (a reasonable first pass is `fires / 4` capped at 1):

   ```rust
   engine.set_loop_volume(ClipId::FireCrackleLoop, 0.8 * fire_target);
   ```

   The bed is global and centre-panned in this slice; per-fire positional loops
   are a later hook.

3. **Lightning and thunder.** On a lightning flash, compute the listener
   distance to the strike column:

   ```rust
   let pan = world_pan(listener, yaw, strike);
   let cue = thunder_cue(distance);
   // Close strikes use ThunderNear, which already carries a crack at arrival.
   // Beyond 64 m the thunder is only a rumble, so add the immediate flash crack
   // if the strike is still close enough to see/hear directly.
   if cue.clip == ClipId::ThunderDistant && distance < 96.0 {
       engine.play_clip(ClipId::LightningCrack, 0.9, Some(pan));
   }
   engine.play_cue(cue, Some(pan));
   ```

   The second call may be scheduled by the caller after `distance / 343` seconds
   for speed-of-sound; the audio crate does not delay it. `thunder_cue` already
   selects near/far variants, gain and pitch.

4. **Explosion and creeper.** On a creeper fuse, play the fuse once; on the
   explosion, resolve distance and pan:

   ```rust
   engine.play_clip_world(ClipId::CreeperHiss, creeper_position, 0.9);
   // later, on detonation:
   let cue = explosion_cue(distance);
   if cue.gain > 0.0 {
       engine.play_cue(cue, Some(world_pan(listener, yaw, blast_position)));
   }
   ```

5. **Bow, arrow and critical hit.** Local bow release and world-space impact:

   ```rust
   engine.play_clip(ClipId::BowShoot, 0.7, None);
   engine.play_clip_world(ClipId::ArrowImpact, hit_position, 0.9);
   engine.play_clip(ClipId::CriticalHit, 0.9, None);
   ```

6. **Mob and XP cues.** World-space cues use the existing 24 m attenuation:

   ```rust
   engine.play_clip_world(ClipId::SkeletonRattle, skeleton_position, 0.7);
   engine.play_clip_world(ClipId::SpiderChitter, spider_position, 0.7);
   engine.play_clip(ClipId::XpPickup, 0.8, None);
   engine.play_clip(ClipId::LevelUp, 0.9, None);
   ```

7. **Fire block material.** Map `openblock:fire` to `ob_audio::Material::Fire` in
   `audio_material_for` so `Sfx::BlockBreak/BlockPlace` use the new fire variants.

One-shots need no handles: the voice pool overlaps them automatically. Loop
targets persist in the mixer and only need to be written when they change (or
each frame, which is harmless). No new thread, dependency or device call is
required.

Results in this environment:

- **49 tests passed, 0 failed.** New coverage:
  - registry uniqueness, stable names, `from_name`, loop flags and enum order;
  - whole-bank determinism (including all four loops), variant coverage, clip
    durations and finite/bounded/audible PCM;
  - rain intensity, thunder/explosion distance cues and hostile-value clamping;
  - constant-power pan, yaw-relative world pan and distance attenuation;
  - loop target sanitising, offline 1.2 s fade-in/fade-out continuity, exact
    silence after stop, and one-shot overlap in the 16-voice pool;
  - stub backend error contract (the stub is compiled into Linux test builds;
    the Pulse path keeps its fake-loader tests);

  **39.21 ms** startup synthesis, **1.17 ms** to mix one stereo second
  (about 0.020 ms per 60 Hz frame). This is the debug/test profile; release is
  faster. PCM memory is **18.0 MiB**.

## 6. Limitations and remaining hooks

- No per-distance low-pass/reverb/occlusion or Doppler; thunder/explosion
  distance is encoded as clip choice, gain and rate. No speed-of-sound delay is
  applied by `ob_audio`; the client should schedule it.
- Rain/snow/fire beds are single mono centre loops. There is no stereo width,
  per-fire positional loop, or rain/snow blend inside one clip.
- The loop fade is fixed at 1.2 s; there is no per-bed crossfade duration.
- Rain helper values are a first-pass crossfade; listen and tune the 0.65/0.90
  ceiling once the client can play on a real Pulse/PipeWire output.
- The 16-voice pool is unchanged. Thunder/explosion can steal quiet voices.
- No captions, subtitle metadata, loudness normalisation, streaming or hotplug
  recovery in this slice. Windows/macOS remain the silent stub.
- Actual device listening is still required on Linux; CI exercises synthesis,
  mixing and the stub without opening a window or audio device.

- Do we want speed-of-sound delay handled inside the audio engine rather than scheduled by the client?
- Should thunder/explosion get distance low-pass/occlusion, and does the Pulse mixer have headroom for it?
