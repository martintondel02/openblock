# 1.2 client integration — use routing, light sync, sleep UI and content UX

> Status: implemented on `v1.2-dev` (client slice). Last updated: 2026-11-25.
> Scope: `crates/client/**` on top of the server/gameplay slice `b18b551`,
> protocol **v3** (additive `UseBlock`, `SleepRequest`/`Wake`, `LightUpdate`,
> `TimeSync`, `SleepState`). Offscreen screenshots and loopback tests only; no
> window and no client-side light computation.

## 0. What shipped

| Area | Result |
| --- | --- |
| Use routing | right-click classifies the target/held stack; single-player calls `Host::use_block_at`, multiplayer sends `UseBlock`/`SleepRequest`; every server rejection becomes a short HUD hint |
| Farming/torches | hoe→farmland, seeds→wheat, harvest, torch place/break and bed use all work through the normal Use binding; containers/crafting tables unchanged |
| Sleep | personalised `SleepState` overlay (`x/y players sleeping`, `waking in N`), 100-tick countdown bar, HUD/interaction gating, `Wake` on move/damage/Esc; single-player uses `Host::sleep_state`/`wake`, multiplayer waits for the server vote |
| Light sync | dense `LightUpdate` decoded with `decode_light_words` on the reader thread, replaced verbatim in replicated sections, touched section + changed snapshot-border neighbours remeshed; unloaded/stale sections dropped safely |
| Clock | `TimeSync` drives `server_tick`/`day_phase`/`day_ticks`, including the sleep skip (no local `% 24_000`) |
| Content UX | 1.2 item icons/tooltips, creative palette order, crafting rows and inventory capture seeded with all new items |
| Tests | interaction matrix, sleep overlay, dense-light apply/border invalidation, single-player dirty-once, loopback use/sleep/light, screenshot flag parsing |
| Screenshots | torch room, wheat farm, sleep overlay, 36-slot inventory and compact 960×540@125 inventory |

## 1. Right-click / use routing

`crates/client/src/interaction.rs` owns the pure classifier used by both
runtimes:

```text
route_use(registry, target, selected, creative) -> CraftingTable | Container | UseBlock | Place
```

| Target | Held stack | Route | Why |
| --- | --- | --- | --- |
| crafting table | any | `CraftingTable` | existing modal screen |
| furnace / chest | any | `Container` | existing `UseBlock` window request |
| bed foot/head | any | `UseBlock` | multiplayer sends `SleepRequest`, SP calls `use_block_at` |
| `wheat_0..3` | any | `UseBlock` | harvest; cross blocks are not placement targets |
| grass / dirt | hoe | `UseBlock` | server tills + wears the tool + broadcasts farmland |
| grass / dirt | placeable block | `Place` | building still works; no doomed `needs_hoe` request |
| grass / dirt | empty/other | `UseBlock` | surfaces the authoritative `needs_hoe` hint |
| farmland | seeds | `UseBlock` | server consumes one seed and plants |
| farmland | placeable block | `Place` | placing above farmland still works |
| farmland | empty/other | `UseBlock` | surfaces `needs_seeds` |
| torch/stone/other | any | `Place` | normal eat/place path |
| any | any | creative | placement path for grass/dirt/farmland (palette holds blocks, not hoes) |

Single-player uses the host outcome directly: tilling reports *Tilled
farmland*, planting *Planted wheat*, harvesting lists the drops, tool breakage
uses the existing warning/SFX path and a daytime bed use still reports the
personal respawn point. Multiplayer sends one intent and never predicts item
counts, durability, crops or light; server `ActionRejected` reasons are mapped
by `net_state::friendly_action_rejection`:

| Reason | Toast |
| --- | --- |
| `needs_hoe` | Hold a hoe to till grass or dirt |
| `needs_seeds` | Hold seeds to plant on farmland |
| `occupied` | That space is occupied |
| `too_dark` | Too dark to plant here - crops need light 9 |
| `not_night` | You can only sleep at night |
| `obstructed` | The bed is obstructed |
| `bed_malformed` | That bed is broken |
| `not_interactable` | That block cannot be used |
| `out_of_reach` | Too far away |
| `no_support` | That block needs support |
| `not_held` | Select the matching item first |
| `player_overlap` | You are standing there |
| `invalid_block` | That block cannot be placed |
| `sleeping` / `already_sleeping` | You are already sleeping |

Use hints for `use_block`/`sleep` omit the `(action)` debug suffix; edit and
inventory rejections keep it for troubleshooting.

## 2. Sleep UI and state

### 2.1 Network decode

`NetworkClient` stores the latest personalised `SleepView`:

```text
sleeping, bed, sleepers (sorted/capped), all_sleeping, skip_remaining_ticks
```

`NetworkClient::send_sleep_request(pos)` sends `SleepRequest`; `send_wake()`
sends `Wake`. Both share the server's 2/s rate limit. Bed use routes through
`SleepRequest` (the explicit v3 intent), every other use through `UseBlock`.

### 2.2 Overlay

`ui_state::SleepOverlay` + `draw_sleep_overlay` render a dark dimmer and a
compact-safe centred panel:

```text
Sleeping
1/2 players sleeping
Waiting for other players      (vote incomplete)
Waking in 70 ticks              (skip running, bar = 1 - remaining/100)
Move or press Esc to wake
```

Gameplay HUD (crosshair, hotbar, selected-name, toasts, player list, chat) is
suppressed while asleep, and use/mine/inventory/hotbar/container actions are
gated. Movement keys and Esc send `Wake`; damage wakes server-side and the
client also sends `Wake` defensively. Single-player increments a display
countdown while `Host::sleeping()` (the host skips the clock 100 simulated
ticks); multiplayer uses the authoritative `skip_remaining_ticks`.

### 2.3 Respawn text

The single-player death screen reads `Host::respawn_point()` and shows
*Respawn at your bed* instead of the world-spawn note once a valid bed has been
used. The multiplayer death screen remembers the last bed observed in
`SleepState` and uses the same wording while keeping the server
inventory note.

## 3. LightUpdate application (multiplayer)

1. **Decode off the render thread.** `reader_loop` matches `LightUpdate`,
   takes at most `MAX_LIGHT_SECTIONS_PER_UPDATE` sections, checks
   `format == LIGHT_SECTION_FORMAT`, decodes `encoding` 0/1 with
   `decode_light_words` and pushes `Inbound::Light { tick, sections }`. A
   malformed section is dropped; it does not kill the batch or the connection.
2. **Replace, never relight.** `NetworkClient::apply_light_batch` ignores a
   batch older than `light_stats.last_tick`, drops sections whose column is not
   resident and calls `apply_light_section`. That writes all 4,096 packed words
   through `Section::light_mut()`, compacts an all-equal container, and does not
   call `relight_around`/`relight_all`.
3. **Border-aware remesh.** While writing, the function records every section
   offset in the 3×3×3 neighbourhood whose one-block snapshot border contains
   a changed cell: a face change touches one neighbour, an edge two, a corner
   seven (including diagonals). It always marks the edited section dirty and
   marks each resident affected neighbour dirty too, because a worker
   `SectionSnapshot` captures a full one-block border and its smooth light/AO
   depends on those words.
4. **Frame budget.** The existing `NetApp::stream_and_mesh` scheduler consumes
   `World::take_dirty_sections` once per frame with `MAX_MESH_SUBMISSIONS_PER_FRAME`
   snapshots; overflow is re-marked dirty and retried. Far sections invalidate
   their merged LOD batch instead. Decoding 64 sections happens on the reader
   thread, so the main thread only copies words and schedules meshes.
5. **Counters.** `LightSyncStats { batches, sections, sections_dropped,
   neighbour_remeshes, last_tick }` is exposed for F3/diagnostics and tests.

Single-player already consumed `Host::take_dirty_sections` exactly once in
`GameState::stream_and_mesh`; a new integration test pins the contract for a
torch at a section border and verifies the worker mesh carries block light.

## 4. Content UX

* Seeds/wheat/bread already had procedural icons from the inventory slice;
  hoe icons resolve through `HotbarIcon::Tool { kind: Hoe, tier }` and the
  inventory footer shows tier/durability/speed (`Iron Hoe · Durability
  250/250 · Speed 6.0`).
* The creative palette lists the append-only 1.2 block ids in content order:
  torch, farmland dry/wet, wheat 0–3, bed foot/head. A unit test pins the order
  and every block-item icon.
* Crafting already reads the registry recipes; the screen shows Torch, Bread
  and the three hoes in Building/Tools with the same availability rules. The
  existing crafting tests cover the 1.2 rows, gating and output info.
* The 36-slot survival inventory capture now seeds all 1.2 items (torch,
  seeds, wheat, bread, three hoes, both bed halves, wheat stage, farmland) so
  the icons and the hoe tooltip are visible in one frame.
* Control hints now say `RMB use/eat/place` (single-player HUD) and
  `RMB use/eat/place` (multiplayer HUD); CLI help documents the new capture
  flags.

## 7. Remaining work and limitations

* **No multiplayer crafting table.** It is outside this slice's server change
  set; the client keeps the existing `Crafting is not available in multiplayer
  yet` hint and the recipe catalogue is ready for a later wave.
* **No client-side light prediction.** Multiplayer applies only server
  `LightUpdate` batches. Existing predicted block edits still run the world
  crate's local relight for immediate visual feedback, then the authoritative
  dense patch replaces the section; block-use actions (till/plant/harvest/sleep)
  are never predicted. If strict no-local-relight prediction is wanted, the
  world crate needs a light-free `set_block` variant, which is outside this
  slice.
* **Sleep countdown in single-player is presentation-only.** The host does not
  expose `SleepSkip`, so the overlay counts simulated ticks from bed entry; the
  actual wake/sunrise timing still comes from `Host::sleep_state()`.
* **Multiplayer respawn text is a remembered hint.** The protocol has no
  personal-respawn field outside `SleepState`; the death screen shows the last
  bed observed, while the actual respawn position stays server-authoritative.
* **Bed orientation** remains fixed +Z pillow; wall torches remain unsupported
  (1.2 scope).
* **No particles/SFX for tilling/planting/sleep** beyond the shared block
  place/break/eat sounds; not protocol-gated.
* **GPU readback light test is a screenshot, not an assertion.** The loopback
  test asserts decoded words, border dirty sections and a worker mesh with lit
  torch vertices; the visual proof is the offscreen torch capture.
