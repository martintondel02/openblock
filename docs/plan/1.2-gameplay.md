## 1. Light and save integration

### 1.1 Migration on open

`Host::open` now calls `ob_world::load_world_dir_with_report(registry, &world_dir)`.
For a 1.0/1.1 save (no marker or `light_version < 2`) the loader relights every
resident column, rewrites `world.obs` in the unchanged v4 format and writes
`world_meta.txt` with `light_version=2`. The host logs:

```text
light migration relit <N> chunks, rewrote save/meta (light_version=2)
```

`N` is `world.chunk_count()` of the migrated world. A second load sees the
marker and does not relight. `world.obs` remains the only source of blocks; the
sidecar is additive and safe to delete (deleting it forces a relight).

### 1.2 Marker after commit

The sync path writes the marker only after `save_worker::commit` renamed every
staged file (sidecars first, `world.obs` last). The async `SaveJob` carries
`light_version` and the worker writes the marker after the same commit; it never
marks a save that failed. If a marker write fails, the world snapshot is still
valid and the next load simply relights.

### 1.3 State hash

`Host::state_hash` now writes:

* `0xF5` + `World::light_hash()` (canonical per-cell light words, cached);
* `0xF6` + the personal respawn point (present/absent + quantised coordinates);
* `0xF7` + crop count and each crop sorted by id (`id`, position, stage, age,
  hydrated).

The old seed-42 fixture `eba0c42219691190` is intentionally obsolete.

### 1.4 Dirty-section contract

`World::set_block` marks the edited section and its snapshot-border neighbours
dirty; every light write marks the touched section dirty; bulk sky writers mark
the whole relight box. `Host::take_dirty_sections` exposes the set exactly once
(no duplicates), so a client remesh scheduler sees light-touched sections without
a second relight call. A server-side test places a torch at local x=14 and
asserts the neighbour section (where the level reaches) is dirty and unique.

## 2. Protocol additions (still v3)

All additions are additive serde variants with new `"type"` tags; no existing
field, slot address or payload changed. Unknown-variant clients already ignore
them. See spec 18 §3.13.2 and §3.13.10.

| Dir | `type` | Fields |
| --- | --- | --- |
| S→C | `light_update` | `tick: u64`, `sections: [{cx, cy, cz, format: u8, encoding: u8, data: base64}]` |
| S→C | `time_sync` | `tick: u64`, `day_phase: u64`, `day_ticks: u64` |
| S→C | `sleep_state` | `sleeping: bool`, `bed?: [i32; 3]`, `sleepers: [u64]`, `all_sleeping: bool`, `skip_remaining_ticks: u32` |
| C→S | `sleep_request` | `pos: [i32; 3]` |
| C→S | `wake` | — |

### 2.1 LightUpdate payload

* Dense 4,096 packed words per section (`[sky:4][R:4][G:4][B:4]`), canonical
  `LocalPos` order.
* `format = 1`; `encoding = 0` raw little-endian `u16` (8,192 B) or
  `encoding = 1` zstd level 1 (used when strictly smaller). Decode with
  `ob_protocol::decode_light_words`.
* `MAX_LIGHT_SECTIONS_PER_UPDATE = 64`; worst-case base64 is well under
  `MAX_FRAME_LEN = 2 MiB`.
* At most one batch per player per tick; 10/s rate limit with a 20-frame burst.
* Per-client reliable queues: out-of-range/unloaded sections are pruned, a
  rate-limited client keeps its queue, and a section is removed only after its
  batch is sent.
* Generated chunks are **not** sent as `LightUpdate`: their words travel in
  `chunk_data`, and the server drains generation dirty marks after streaming.
* Interest is Chebyshev chunk distance (`interest_radius_chunks`); Y is not
  filtered because a relight reaches across section boundaries.

### 2.2 Time and sleep

`time_sync` is sent in the handshake, at 1 Hz, and every tick while a skip runs.
`sleep_state` is personalised, sent in the handshake, on transitions, at 2 Hz
and every tick during a skip. `sleep_request`/`Wake` are rate-limited to 2/s
(burst 4). A Move from a sleeping client wakes it before applying the move.
Damage clears the sleeper and the skip.

## 3. Mechanics

### 3.1 Torches

* Placement through the normal block-place path (single-player
  `apply_action_with_outcome`, network `BlockEdit`), selecting the torch item.
* Requires an air target, a loaded column and a **solid block directly below**
  (`World::is_solid`); wall placement is rejected in 1.2 with no item consumed.
  Network rejection reasons: `no_support`, `occupied`, `out_of_reach`,
  `not_held`, `player_overlap`.
* Torch light 14 comes from content (`BlockType::emission`), so the existing 31³
  edit relight propagates it.
* Breaking the support removes the torch above and relights; the torch drops
  through the normal drop table. Creative removal also removes the torch.
* Torch state is world blocks only, so it persists in `world.obs` and the state
  hash via blocks + light.

### 3.2 Farming

`UseBlock` on grass/dirt with a `ToolKind::Hoe`:

* swaps the block to `farmland_dry` (or `_wet` if water is already in range);
* wears one tool point (59/131/250 for wood/stone/iron), removing the tool at
  zero and reporting it;
* records the block update for multiplayer replication.

Seeds on farmland:

* require an air cell above, a loaded column, and
  `gameplay_light(crop, day, weather) ≥ 9` (else `too_dark`);
* consume exactly one seed in survival (creative does not consume);
* set `wheat_0` above and insert a `CropState` with the next deterministic id.

Growth (`Host::tick` in single-player, `Host::tick_network` in multiplayer):

| Rule | Value |
| --- | --- |
| Stage ticks, dry | `CROP_GROWTH_DRY_TICKS = 2,400` |
| Stage ticks, hydrated | `CROP_GROWTH_WET_TICKS = 1,200` |
| Stages | `wheat_0..wheat_3`; stage 3 stops ageing |
| Light | grows only at `gameplay_light ≥ CROP_MIN_LIGHT = 9`; pauses below |
| Hydration | water within `CROP_HYDRATION_RADIUS = 4` horizontally and ±1 Y, checked every `CROP_HYDRATION_INTERVAL_TICKS = 20` |
| Visual | farmland id swaps dry ↔ wet on a hydration change |
| Mature harvest | 1 wheat + 1–3 seeds |
| Immature harvest | 1 seed |
| Grass break | dirt + seeds with `GRASS_SEED_DROP_MODULUS = 8` (12.5%) |

Harvest rolls use `mix64(world_seed ^ position ^ salt)`, never RNG state, so
save/reload and replay are identical. `UseBlock` harvests a crop (any item);
breaking also harvests with the same rolls. Breaking farmland removes the crop
above and drops dirt. Crops in unloaded columns are frozen.

`crops.txt` (header-free, sorted by id):

```text
id x y z stage age hydrated
```

A missing file loads as no crops. Rows with an unknown block, non-wheat block,
out-of-world/unloaded position, duplicate id or invalid stage are skipped with a
warning. The visible block stage wins over a stale row. The block-id swap and
hydration swap are broadcast per changed cell as `block_edit`.

### 3.3 Beds, sleep and respawn

* Blocks `bed_foot`/`bed_head`, pillow fixed at +Z; no facing state in 1.2.
* Placing either half validates both cells (air, in-world, loaded), solid
  support under both and no player overlap, then consumes exactly one bed item.
  Breaking either half removes both; the broken half drops one bed item.
* `UseBlock` on either half resolves the pair. Sleep requires distance ≤ 3.5
  metres, phase in `12,600..=23,400`, and two air cells above both halves
  (`obstructed` otherwise). No thunder window exists until 1.3.
* The first use of a valid bed sets the personal respawn point at the foot
  block's top cell even if it is too early to sleep (spec 08 §3.10); the sleep
  itself still requires the window and an unobstructed bed. Later deaths use
  the point before the world spawn.
* Single-player: `Host::tick` freezes the player and fast-forwards to the next
  sunrise over `SLEEP_FAST_FORWARD_TICKS = 100` ticks, adding
  `ceil(remaining/100)` extra clock ticks per tick and clamping exactly to phase
  0. Wake cancels the skip; damage wakes and cancels; removing a bed wakes.
* Multiplayer: denominator = every connected, alive player (creative included;
  no spectator/dimension split in this milestone). All must sleep; then the
  same 100-tick skip runs and everyone wakes at sunrise. One awake player means
  no skip; a partial sleep times out after `SLEEP_REQUEST_TIMEOUT_TICKS = 600`.
  Damage clears that player and the skip; the next tick wakes the rest.

Persistence:

```text
spawn.txt
<x> <y> <z>                 # unchanged 1.0/1.1 world spawn
respawn <x> <y> <z>         # additive personal bed point, optional

network_players.txt
name x y z yaw pitch health hunger dead selected mode r<x>,<y>,<z> [i... e...]
```

Sleep itself is transient; a reconnect starts awake at the saved position with
the saved respawn point.

### 3.4 Light-based hostile spawning

The old day/depth gate is kept, and hostile candidates now additionally require
`World::gameplay_light(feet, day_factor, weather_factor) ≤
HOSTILE_SPAWN_MAX_LIGHT = 7`.
`Host::day_factor` is 1.0 through phase 11,000, ramps to 0 over 11,000–13,000,
is 0 through 13,000–21,000 and ramps back over 21,000–24,000. `weather_factor`
is 1.0 (`CLEAR_WEATHER_FACTOR`) because 1.3 owns weather. The 16–48 m ring,
8 m minimum, caps, despawn and zombie day-burn are unchanged. A torch at level
14 falls below 8 after six lateral steps, suppressing spawns in roughly a
7-block radius; a sealed dark cave remains spawnable. `Host::hostile_spawn_light_ok`
is the predicate used by both spawning and tests.

### 3.5 Interaction routing and rejection reasons

`UseBlock` (network) / `Host::use_block_at` (single-player) is server-authoritative:

| Target | Result |
| --- | --- |
| grass/dirt + hoe | till; `needs_hoe` if no hoe |
| farmland + seeds | plant; `needs_seeds`, `occupied`, `too_dark` |
| wheat | harvest; deterministic drops |
| bed | sleep; `not_night`, `obstructed`, `bed_malformed`, `out_of_reach`, `already_sleeping`, `dead` |
| torch/other | `not_interactable` or `no_block` |
| out of reach/unloaded | `out_of_reach` / `unloaded` |

Block placement via `BlockEdit` returns `invalid_block`, `occupied`,
`no_support`, `not_held`, `player_overlap`, `invalid_position`; the network
handler never trusts client inventory, light or support state. Bread keeps food
5 through content; seeds/wheat remain inedible and the existing eat/equip logic
is untouched.

## 4. Public host/network APIs for the client slice

Single-player (`Host`):

* `use_block_at(BlockPos) -> Result<ActionOutcome, String>` — hoe/plant/harvest/sleep.
* `sleeping()`, `sleep_state() -> Option<SleepState>`, `wake() -> bool`.
* `respawn_point() -> Option<WorldVec>`; `respawn()` uses it.
* `crop_count()`, `crops()`, `crop_stage(pos)`.
* `day_factor()`, `weather_factor()`, `is_sleep_window()`.
* `hostile_spawn_light_ok(pos) -> bool`.
* `take_block_updates()`, `take_dirty_sections()`, `world().light_hash()`.
* `set_tick_count(u64)` — admin/test seam for starting at night; not wired.

Network (`Host` + `net`):

* `network_use_block(id, pos)`, `network_sleep_request(id, pos)`,
  `network_wake(id)`, `network_sleep_snapshot()`.
* `Host::take_block_updates()` is drained by the net tick and broadcast as one
  `block_edit` per changed cell.
* Light changes are collected per client in `net.rs` and batched as
  `light_update`; sleep/time sync is broadcast as described above.

## 6. Remaining client work

Owned by the following client agent; the server is ready:

1. **Use routing.** Right-click must call `Host::use_block_at` in single-player
   and send `use_block` in multiplayer instead of the current container-only
   hard-coded branch. Show the server's `action_rejected.reason` as a hint.
2. **Sleep overlay and time.** Consume personalised `sleep_state`, render the
   sleep screen/overlay with the sleeper list and countdown, send
   `sleep_request`/`Wake`, and use `time_sync` (not a local clock) for the sky
   during a skip. Single-player can read `Host::sleep_state()`/`tick_count()`.
3. **LightUpdate application.** Decode with
   `ob_protocol::decode_light_words`, replace every named section's light, and
   mark that section plus its snapshot-border neighbours for remesh. Do not
   predict light; generated chunks already carry their words in `chunk_data`.
4. **Crop/bed rendering.** Already content-driven (`wheat_0..3` cross quads,
   `farmland_dry/wet`, `bed_foot/head` cubes, torch cross); only model/orientation
   polish (bed pillow is always +Z) remains.
5. **Particles/SFX** for tilling, planting, harvest, torch and sleep are optional
   presentation work and not protocol-gated.

## 7. Risks and deliberate deviations

* **Sleep denominator.** 100% of connected alive players including creative; no
  spectators or dimensions in 1.2. The spec target allows a configurable
  percentage and dimension split later.
* **No thunder window.** 1.3 owns weather; beds are usable only in the night
  window. No bed explosion outside the overworld (there is one dimension).
* **No bed facing.** Fixed +Z pillow; bed placement requires floor support under
  both cells. No wall torches.
* **Crops are not block entities.** `crops.txt` is a separate host sidecar and a
  crop does not tick in an unloaded column; there is no random-tick model.
* **Hydration uses farmland block-id swaps**, not block states; a future
  block-state wave can replace the swap without changing the sidecar.
* **The skip advances the clock, not simulation.** Mobs, crops, furnaces and
  items tick once per simulated tick during the 100-tick fast-forward; only
  `tick_count`/day phase jump to sunrise. This keeps the skip cheap and
  deterministic and matches the 1.2 scope (no random-tick catch-up).
* **Relight-on-load is intentionally conservative.** A marked v2 save skips it;
  an unmarked save pays one full relight. `world_meta.txt` is written after the
  commit, so an interrupted save can at worst cause one extra relight, never a
  false migration marker.
* **Workspace-wide checks.** `crates/client` will need to handle the new variants
  (it already has a wildcard) and apply light/sleep; only `ob_protocol`,
  `ob_server`, `ob_core` were required to be green in this slice.

## 9. Open questions

1. **Sleep denominator scaling.** 1.2 uses 100% of connected alive players. A
   later wave may expose `players_sleeping_percentage`; the host snapshot
   already isolates the calculation in `Host::network_sleep_snapshot`.
2. **Weather window.** Beds currently accept only the night window. 1.3 owns
   thunder, so the window predicate is the single place to add it.
3. **Crop block states.** Hydration is encoded by id swaps because 1.2 has no
   block states; a future state palette can replace the swap without changing
   `crops.txt`.
4. **Fast-forward simulation.** The skip advances the clock only. If a later
   wave wants crops/furnaces to catch up, it needs a bounded catch-up budget so
   a 10,000-tick skip stays within the tick envelope.
