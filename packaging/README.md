# Packaging

OpenBlock is **Linux-first and Fedora-first** ([DEC-054](../docs/decisions.md)): the
supported window is Fedora's current + previous release at any ship date
(Fedora 44/45 while this packaging was written), so the RPM and Flatpak builds
move forward with Fedora's cycle.
This directory holds the packaging sources for the primary platform; the
secondary platforms' packaging is described in
[spec/22](../docs/spec/22-platforms-and-distribution.md).

## Artifact priority

| Priority | Artifact | Audience | Source of truth |
| --- | --- | --- | --- |
| 1 | **Flathub Flatpak** (`io.github.martintondel02.OpenBlock`) | Fedora and other Linux players | `packaging/flatpak/` |
| 2 | **COPR RPM** `openblock` (client) and `openblock-server` | Fedora users who prefer native packages and system integration | `packaging/fedora/openblock.spec` |
| 3 | AppImage and `.tar.zst` | Portable/manual installs, other distributions | generated by `xtask dist` |
| 4 | Official Fedora repository package | Long-term goal; requires unbundling Rust crates via cargo2rpm | OPEN-021 |
| 5 | Server container image | Cloud and non-Fedora hosts | `Dockerfile` at the repo root (added at MS-07) |

The Fedora RPM currently bundles the Rust crates and is therefore a **COPR
package, not Fedora-repository-compliant**. That is a deliberate, documented
trade-off until OPEN-021 is decided; the Flatpak has the same bundling model and
is the player-facing default.

## Build and verify locally (Fedora 44/45)

```sh
# Build a local RPM from a source tarball produced by `cargo xtask dist`
rpmbuild -ba packaging/fedora/openblock.spec

# Lint and verify the units/metadata
rpmlint packaging/fedora/openblock.spec
desktop-file-validate packaging/fedora/io.github.martintondel02.OpenBlock.desktop
appstreamcli validate --no-net packaging/fedora/openblock.metainfo.xml
# The unit is validated with a stub binary and without man-page lookup until the
# server binary exists (the RPM install test at MS-16 validates it for real).
sudo install -Dm755 /bin/true /usr/bin/openblock-server
sudo systemd-analyze --man=no verify packaging/fedora/openblock-server.service

# Flatpak
flatpak-builder --user --install --force-clean build-dir packaging/flatpak/io.github.martintondel02.OpenBlock.yml
flatpak run io.github.martintondel02.OpenBlock
```

CI runs the same checks in `fedora:44` and `fedora:45` containers; see
[`.github/workflows/ci.yml`](../.github/workflows/ci.yml).

## Dedicated server on Fedora Server

```sh
sudo dnf copr enable openblock/openblock
sudo dnf install openblock-server
sudo systemctl enable --now openblock-server
sudo firewall-cmd --permanent --add-service=openblock-server
sudo firewall-cmd --reload
journalctl -u openblock-server -f      # join ticket is printed here
```

The unit is sandboxed (`ProtectSystem=strict`, `ProtectHome=true`,
`NoNewPrivileges=true`, `PrivateTmp=true`) and keeps worlds, backups and content
in `/var/lib/openblock-server` via `StateDirectory`. SELinux stays enforcing:
no custom policy module is required or shipped. See
[spec/19 §3.1.1](../docs/spec/19-server-administration.md#311-fedora-server-primary-deployment).

## Files

| File | Purpose |
| --- | --- |
| `fedora/openblock.spec` | RPM spec: client, desktop integration, and server subpackage (COPR draft) |
| `fedora/openblock-server.service` | Hardened systemd unit for the dedicated server |
| `fedora/openblock-server.firewalld.xml` | firewalld service definition for the QUIC/UDP port (25565/udp) |
| `fedora/openblock-server.sysusers` | Dedicated system user for the server |
| `fedora/server.toml` | Default server configuration installed by the server RPM |
| `fedora/io.github.martintondel02.OpenBlock.desktop` | Desktop entry (matches the Flatpak app ID) |
| `fedora/openblock.metainfo.xml` | AppStream metadata (required by Flathub and GNOME Software) |
| `fedora/openblock.mime.xml` | Shared MIME-info for `.obworld` archives |
| `fedora/io.github.martintondel02.OpenBlock.svg` | Placeholder icon (CC0; replaced before 1.0) |
| `flatpak/io.github.martintondel02.OpenBlock.yml` | Flatpak manifest (bundled crates, portals) |

## Provenance

All packaging files are MIT OR Apache-2.0 and carry REUSE metadata in
[`REUSE.toml`](../REUSE.toml). The package name and desktop/AppStream IDs are
working identifiers pending trademark clearance (DEC-037); renaming before 1.0
must update this directory, the Flatpak ID and the repository URL in one change.
